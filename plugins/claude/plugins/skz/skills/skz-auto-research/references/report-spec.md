# 汇总报告规范（单文件 HTML）

参考版式骨架：深色侧栏 + 纸感浅色正文，左栏 sticky 目录、编号章节。
`scripts/gen_report.py` 已内置该骨架的同族实现，**默认直接用它产出，别另起一套**。
全流程由 `run_pipeline.sh`/`pipeline.py` 调用真实参数 `--workdir --out --scenario --theme --title`。
报告同时写明流水线 outcome、零库存跳过原因、全部尝试保留费用（含失败/补跑，非扣费账单）。
driver 验证完整章节、锚点、编码及无脚本，并落盘 SHA256 后才发 final_completed。
调用方必须核验 summary/报告并通过宿主附件/文件展示机制交付；paused 或 outcome=failed 不宣称研究成功。
当前模板纯 HTML/CSS 的静态验证不等于浏览器视觉测试。

## 1. 硬性技术要求

- **单文件**：CSS/JS 全内联，无外部依赖、无 CDN。用系统字体栈
  （`"Iowan Old Style", "Palatino Linotype", "Songti SC", serif` + 等宽 `"SF Mono", Menlo, monospace`）。
- **`<!DOCTYPE html>` 必须在文件最开头**；`<meta charset="utf-8">` 必须在**前 1024 字节**内。
  （用编辑器写入中文时最容易踩，写完**必须**验证。）
- 长报告必须有**左侧 sticky 目录**（编号章节锚点）；窄屏退化为单列（`@media (max-width: 900px)`）。
- 表格优先于段落；每章开头一句**加粗结论**，细节在下面。
- 无 JS 依赖最好；若用 JS，数据用内联 `<script id="payload" type="application/json">` + `JSON.parse`，
  别用 `re.sub` 往模板里注入。⚠️ `querySelector` 取不到节点后 `.nextSibling`/`.textContent` 会中断整段脚本，
  表现是**页面全空**——所有 DOM 操作前先判空。
- 交付前自查：把 HTML 丢进浏览器实测一遍（展开目录、点开每张表、缩窄窗口看单列降级）。
  预览服务务必带 charset 头，否则中文乱码；**别用裸 `python3 -m http.server`**。

## 2. 配色：主题化（`--theme`）

配色**不写在 CSS 里**，而是集中在 `scripts/gen_report.py` 的 `THEMES` 字典
（CSS 用 `__XXX__` 占位，`render_css(theme)` 注入）。**改配色只动 THEMES，别动 CSS 结构。**

```bash
python3 scripts/gen_report.py --list-themes          # 列出可选主题
python3 scripts/gen_report.py --workdir <dir> --out <f> --theme vermilion
```

| 主题 | 一句话 | 侧栏 | 强调色 | 什么场合 |
|---|---|---|---|---|
| `crimson` | 酒红 · 深侧栏 | 深酒红 `#2c1118→#471a24` | `#c8102e` | 稳重，偏暖 |
| `vermilion` | 朱砂 · 宣纸 | 墨褐 `#241f18→#332b22` | `#bc3a2c` | 暖调文气，纸感最强 |
| `coral` | 珊瑚玫瑰 · 明亮 | 深玫瑰棕 `#2c1f23→#412d33` | `#e0655b` | 轻快、明亮 |
| `scarlet`（默认） | 正红 · 冷灰 | 近黑中性 `#17181b→#24262a` | `#cc2632` | 冷灰白底、编辑感最锐利 |
| `brick` | 砖红 · 白底 | 深砖红 `#7a2229→#55161c` | `#b8432f` | 红做主角（面积大，慎用） |

语义变量：`--accent`（强调/正收益）、`--accent-deep`（KPI 数字/内联代码）、
`--accent-soft`（引用块底）、`--green`（负收益）、`--gold`（预警边框）、
`--mute`（次要文字）、`--nav-*`（侧栏一族）。

**默认主题由用户选定**：2026-09-20 用五套对比图让用户挑，用户选 **`scarlet`（正红·冷灰）**，
已把 `DEFAULT_THEME` 改为 `scarlet`。挑配色时先用 `--list-themes` 列出 5 套，
再用同一份数据分别按 5 个 `--theme` 出样例给用户看，不要只凭文字描述。

**一条硬教训（2026-09-20 实测）**：用户说"靓丽一些、偏红色系"时，他要的是**精致**
（细线、层次、微阴影、留白），**不是**提高饱和度或扩大红的面积。
把侧栏做成品红渐变 + 粉底正文 + 红字标题 + 红底表头的那一版，直接被评为"太夸张了，审美不行"。
默认口径：**大面积交给中性色**（白底 / 深底侧栏），**红只出现在强调位置**——
KPI 数字、章节顶 2px 细渐变线、正收益数值、内联代码、进度条。
调整时**一次只动一层**（先侧栏，再强调色，最后底），给用户看一版再决定下一版。

**红涨绿跌**（中国习惯）：收益/超额为正 → `--accent` 红；为负 → `--green` 绿。
夏普、通过率等**非方向性指标不要用红绿**，用中性色（`--ink` / `--mute`），避免误读。
- 数值统一格式：收益率/回撤 `+12.34%`（带符号、两位小数）；夏普/卡玛两位小数；
  比例类（留存率、通过率）**同时给百分比与绝对数**（`3.9%（118/3000）`）。
- 缺失值写 `—`，不要写 `null` / `N/A` / `0`（这三者含义完全不同）。
- 每个数字后面**尽量带口径**（窗口、频率、样本量），至少在图注/表头里写一次。

## 3. 报告结构（两种场景共用）

```
① 结论摘要          —— 一句话结论 + 3~5 条要点（都是加粗短句）
② 本次做了什么      —— 参数快照：路线/问题清单、时间窗、触发次数、数据来源、生成时间
③ 因子挖掘结果      —— 仅场景 A：每轮一行（候选/留存/留存率/状态/耗时）+ 路线累计因子数 + 漏斗
④ 策略探索结果      —— problem × route 矩阵：回测数/通过数/通过率/候选数
⑤ 候选明细与样本外  —— 只看 review-matrix 的「后置验证」行；按样本外夏普排序
⑥ 局限与风险        —— 必写清单（见下），逐条一句话
⑦ 下一步 / 审核指引 —— 平台审核页链接 + 审核要点 + "哪些值得优先看"
附录                 —— 命令与字段口径、数据文件路径、可复现步骤
```

### 各章的硬要求

**① 摘要**：每条要点必须是"可被反驳的断言"，不是"我们做了分析"这种废话。
例：`10 轮挖掘在第 6 轮停止（留存 41 < 阈值 50），路线累计 5,847 个因子`、
`6 个研究问题里只有 2 个出候选，共 4 条，样本外夏普中位 0.31`。

**③ 挖掘结果**：每轮一行，列 `轮次 / 候选数 / 留存(有效因子数) / 留存率 / 状态 / 耗时 / 是否早停`。
必须显式写出**批次为什么停**（跑满 10 轮 / 第 k 轮低于阈值 / 平台故障）。
漏斗图用横向条形（`funnel[].{stage, remaining, eliminated}`），别画花哨图表。

**④ 探索结果**：一行一个 (problem, route)。**分母要写清楚**：`n_backtests`（全部回测）vs
`strategy_count`（仍待审核的候选数）vs `passed`（历史通过数）是三个不同东西，别混。
`passed + failed ≠ n_backtests` 要在表注里说明。

**⑤ 候选明细**：
- ⚠️ **`experiment strategies` 的 `metrics` 是全周期口径，禁止拿它排序汇报**。
  排序键 = `review-matrix` 的「后置验证」夏普。
- 每行至少给：`训练集夏普 → 后置验证夏普 → 衰减`，以及 `多头占比 / 空头占比`（判基准）。
- 净敞口 = `多头占比 − 空头占比`；|净敞口| < 0.1 只表明名义多空接近，不能证明市场风险中性。
  现金可作明确标注的参考基准；风险暴露未核实时，不计算或宣称风险调整后的超额收益。
- 异常形态预警（列进单独的 callout，别混在表里）：只用 1–2 个因子、逐年 alpha 全正且单调放大、
  净值夏普 >3 且回撤 <5%、同路线其他候选量级差数倍 → 标注"需人工核验是否存在未来信息"。

**⑥ 局限必写清单**（一条不落，用户会核对）：

1. 全周期指标 ≠ 样本外（给出本批的衰减数字）。
2. 基准口径：列实际可核实的净敞口，现金仅为参考，低净敞口不证明风险中性。
3. 多重检验：N 条候选挑头部，极值天然抬高。
4. 成本口径：平台未约定 → **明确写"单笔收益是否已扣手续费/滑点未知"**。
5. 后置验证段是否已过期（把 `edt` 与生成日期比）。
6. 样本量：验证期长度以问题读回分段为准，有限样本不能证明真实夏普为正。
7. 选择偏差：分母是"全部回测"还是"通过候选"，写清楚。
8. `key_inspect` / 路线逻辑是自然语言，引擎实现口径可能不完全等于文字描述（如涉及时再提）。

**⑦ 审核指引**（固定文案，可直接用）：

> 到胜可知平台「策略管理 → 策略审核」页逐条审核候选：https://quant.shengkezhi.com/
> （功能说明：https://docs.shengkezhi.com/strategy）
> 审核要点：不要只挑历史收益最高的——核对交易成本、验证期稳定性、回撤，
> 以及表现是否符合原路线的逻辑。审核通过后需**单独**保存入库，入库即 `暂停` 态。

## 4. 命名与落盘

```
reports/skz自动投研_<路线名或问题名>_<YYYYMMDD>.html
state/<同名目录>/          ← 编排状态与抓取的原始 JSON（可复现、可续跑）
```

文件名避免超长与特殊字符；中文文件名在链接里要 `urllib.parse.quote`。
