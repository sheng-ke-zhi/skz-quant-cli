# 策略探索覆盖与执行建议

当用户想知道「下一步该探索什么」「哪些研究问题还没配过某条因子路线」「怎样补齐策略探索覆盖」时，帮助他们把有限的探索预算投向最值得先验证的组合。

## 目标

在**现有研究问题 × 现有因子路线**的范围内，让每个组合至少完成一次探索，并尽量留下可用的入库策略。不要把覆盖清单当作机械待办：结合用户的研究目标、路线的经济逻辑和问题的品种/频率，为用户提出有理由、可选择的下一批建议。

## 建议应回答什么

先让用户看清研究版图，再提出下一步。好的输出通常包括：

- 当前覆盖概览：多少组合尚未探索、多少已探索但没有可用产出、多少已有有效策略；
- 值得优先探索的 `(研究问题, 因子路线)`，以及它为何值得先做；
- 可能需要重探的组合，例如只留下废弃策略，或已有实验但尚未产出策略；
- 正在运行的组合和无法归属的历史策略，单列说明，不把它们误算进覆盖；
- 让用户选择下一批，而不是替用户自动启动探索。

优先级以研究缺口为主：从未执行过探索的组合优先；已执行但没有有效产出的组合可作为下一层候选。相同优先级内，不必死板排序——可以根据用户当前目标、路线与问题的匹配度、研究多样性和已有结果提出判断，并说清理由。

## 覆盖口径

把「至少执行一遍」和「最好有策略产出」分开，不用一个笼统的“已覆盖”掩盖差异：

| 状态 | 含义 | 建议含义 |
|---|---|---|
| 未执行 | 没有该组合的实验记录 | 最高优先级的覆盖候选 |
| 已执行，未产出 | 有实验记录，但没有有效入库策略 | 已满足执行覆盖；可结合结果建议重探 |
| 有有效产出 | 有字段完整、未废弃的入库策略 | 执行与产出覆盖均满足 |
| 仅废弃产出 | 只剩废弃策略 | 不算有效产出；提示可重探 |
| 运行中 | 该组合已有活动探索 | 不建议重复启动，提示等待或跟进 |

历史策略缺少研究问题或因子路线时，无法可靠归入矩阵。单列为「无法归属的历史策略」，不要拿它填充任何组合，也不要猜测归属。

## 适度的工作流程

用免费只读数据建立判断，不需要新增 CLI 命令或共享脚本：

1. 读取现有问题与路线，确定本次分析的矩阵边界；
2. 读取实验和策略，识别执行记录与有效产出；策略清单必须翻页读完，不能按默认第一页下结论；
3. 读取活动探索，避免把正在运行的组合推荐为新的启动项；
4. 按上面的口径形成覆盖视图，再围绕用户的目标给出建议。

可使用的读命令包括：

```bash
skz problem list
skz factor-routes list
skz experiment list
skz strategy list --page-size <N>
skz explore runs --status active
```

这里的工作流程是为了防止遗漏和重复扣费，不是限制推理方式。根据用户问题决定呈现粒度：用户只问“下一步做什么”时给出最有价值的少量建议即可；用户要盘点时再展示完整矩阵或汇总。

## 行动边界

这项能力只生成研究建议：

- 不因分析结果自动创建研究问题或因子路线；
- 不自动触发 `skz explore start`；
- 用户选定组合后，仍按探索流程说明核心假设、代价与预期失败信号，并在付费触发前获得明确确认。
